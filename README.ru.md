## ✨ Зачем это нужно

EasyMax — это панель New API с **обычной регистрацией по имени пользователя + паролю + e-mail** (Turnstile отключён, подтверждение e-mail не требуется), приветственная квота которой зависит от **инвайт-кода**: регистрация без него даёт `quota: 0`, и её ключ отвечает `403 用户额度不足`, тогда как та же регистрация с `aff_code` даёт **250000 квоты (≈ $0.50) на аккаунт** — замерено 2026-10-19, и именно поэтому этот инструмент вообще существует. Единица масштабирования — *один аккаунт на ключ*; инструмент превращает это в `keys.txt`, где **каждая строка прошла живой вызов чата**, по одному закреплённому выходному прокси на аккаунт, почтовый ящик из вашего собственного почтового канала.

## 🎁 Бесплатный тариф — сколько вы получаете

**Каждый аккаунт пополняется инвайт-кодом, который вы отправляете при регистрации** — в этом весь бесплатный тариф.

| Что | Значение |
| --- | --- |
| Приветственная квота | **250000** (≈ $0.50) на аккаунт, расходуется за токен в группе ключа |
| Откуда берётся | `POST /api/user/register?turnstile=` с `aff_code=<code>` |
| Без инвайт-кода | `quota: 0` → ключ отвечает `403 用户额度不足` на каждой платной модели |
| Требуется карта | **Нет** |
| Капча | **нет** — Turnstile отключён при регистрации и входе (`?turnstile=` принимает пустое значение) |
| Подтверждение e-mail | **не требуется** — панель сохраняет адрес и никогда не отправляет код |
| Единица масштабирования | **один аккаунт = один ключ** → `--count N` на самом деле означает «N пополненных аккаунтов» |

`--aff` по умолчанию использует собственный инвайт-код флота; укажите свой — и каждый созданный вами аккаунт начислит вам комиссию панели (10 % для этой панели).

> 💡 Бесплатный тариф устанавливается EasyMax и может измениться. Проверяйте актуальные цифры на [easymax.ai](https://easymax.ai) — и пусть решение принимает собственный контроль инструмента:

```bash
node src/cli.js --verify-only     # каждый ключ в keys.txt перепроверяется реальным вызовом чата
```

| ID модели | Группа токена | ✓ |
| --- | --- | --- |
| `deepseek-v4.1-flash` | `deepseek` (по умолчанию) | ✓ |
| `deepseek-v4-pro` | `deepseek` | ✓ |
| `gpt-6-luna` | `default` | ✓ |
| `gpt-5.6-luna` | `default` | ✓ |
| `gpt-6.1-sol` | `default` | ✓ |

`GET /v1/models` возвращает ровно список группы: **2 id** для ключа группы `deepseek`, **14 id** для ключа группы `default` (`gpt-5.5`, `gpt-5.5-openai-compact`, `gpt-5.6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-6-astra`, `gpt-6-luna`, `gpt-6-sol`, `gpt-6.1-sol`, `gpt-5.3-codex-spark`, `codex-auto-review`, `gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst`). Инструмент по умолчанию создаёт `--group deepseek`, потому что эти id самые дешёвые за токен, поэтому аккаунт с квотой 250000 держится на них дольше всего; передайте `--group default` (или любое другое имя группы, которое предоставляет панель), чтобы вместо этого создать ключ для этого семейства.

## 🧪 Как использовать API

Базовый URL — **`https://easymax.ai/v1`** — совместим с OpenAI, поэтому работает всё, что говорит на OpenAI (SDK, Cursor, OpenCode, Kilo Code, …).

```bash
curl https://easymax.ai/v1/chat/completions \
  -H "Authorization: Bearer <your key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4.1-flash","messages":[{"role":"user","content":"hi"}],"max_tokens":16}'
```

Id `deepseek-v4-pro` — это модель рассуждений: она отвечает сначала `reasoning_content`, а `content` только после бюджета размышлений, поэтому задавайте `max_tokens` значительно выше 100, иначе увидите пустой `content`.

## 🚀 Одна команда

```bash
node src/cli.js --count 10
```

Это весь инструмент: один аккаунт EasyMax на ключ (пополняется инвайт-кодом), его API-ключ создаётся и сохраняется **только** после живого `chat-200`. Шаг с капчей автоматический — EasyMax поставляется с *отключённым* Cloudflare Turnstile (панель принимает пустой `?turnstile=`), поэтому `--auto` (включён по умолчанию) не требует браузера; `src/solver.js` — это то место, где это выражено. Файл `proxies.txt` рядом с репозиторием подхватывается автоматически (один закреплённый выход на аккаунт); без него запуск идёт напрямую.

`--dry` выводит разрешённый план — количество, размер пула, доступность решателя, модели — и завершается, не трогая ни одного файла и не делая ни одного запроса:

```bash
node src/cli.js --dry
```

Предпочитаете меню вместо флагов? `npm start` (или `node src/launcher.js`) → **1) Mint keys** → *How many keys? [10]*.

> ⚠️ **Условия и риск для аккаунта.** Этот инструмент автоматизирует создание аккаунтов и выдачу API-ключей на сторонней панели. Это может нарушать Условия обслуживания панели и привести к блокировке аккаунтов, ключей или IP-адресов. **Автоматизация — ваша собственная ответственность**: прочитайте условия провайдера, используйте свой собственный почтовый ящик и прокси и убедитесь, что вам разрешено делать это в вашей стране, прежде чем запускать.

## 🛠 Быстрый старт

```bash

# clone or fork this repository, then:
cd easymax-bulk-apikey

# 1) your proxy list, one per line (http://…, socks5://… or socks4a://…) — optional
printf 'http://127.0.0.1:8080\n' > proxies.txt   # optional — without it the tool runs direct

# 2) go — one command
node src/cli.js --count 50
# or the menu:  node src/launcher.js        (interactive)
```

Ключ добавляется в `keys.txt` **только** после того, как живое завершение чата подтвердит его; аккаунт, который так и не дошёл до этого момента, записывается в `accounts.json` и повторяется при следующем запуске.

### 🖱️ Лаунчер

`npm start` (или `node src/launcher.js`) — это меню-форма того же CLI: **1) Mint keys** → *How many keys? [10]* (Enter принимает 10) запускает `node src/cli.js --auto --count N`. Он никогда не спрашивает про капчу, токен или прокси — `proxies.txt` используется автоматически, если присутствует. Завершается сводной таблицей (живые/всего, задержка, классы ошибок) плюс путь к `keys.txt`; ключи, не прошедшие контроль, попадают в `keys-dead.txt`.

## ✅ Проверено в работе — каждый ключ протестирован

| Проверка | Результат |
| --- | --- |
| регистрация `POST /api/user/register?turnstile=` | **200** `{"success":true}` — с `aff_code` аккаунт получает `quota: 250000` |
| вход `POST /api/user/login?turnstile=` | **200** — полезная нагрузка New-API **v2** (`access_token` JWT + сессия) |
| авторизация | `Authorization: Bearer <access_token>` + `New-Api-User: <uid>` на `/api/token/*` |
| ключ | `POST /api/token/ {group}` → **200**, затем `POST /api/token/<id>/key` → полный ключ |
| контроль чата — выполняется для **каждого** ключа перед записью | **200** с реальным содержимым |
| ключ, не прошедший проверку чата | никогда не записывается в `keys.txt` (аккаунт остаётся пригодным для повторного использования в `accounts.json`) |

Создано этим инструментом во время сборки: **8 аккаунтов / каждый ключ, все `quota 250000`, все chat-200** на `deepseek-v4.1-flash`, через два типа туннелей (CONNECT + SOCKS5) и 4 выхода.

> **Контроль качества.** Каждый ключ здесь прошёл живой `chat-200` до того, как был записан в `keys.txt`
> (мёртвые ключи никогда не поставляются). Комбинации роутера следуют тому же правилу на уровне модели: запись
> добавляется **только если модель отвечает `chat-200` и умеет вызывать инструменты** — модель без поддержки инструментов,
> мёртвый ключ или мёртвый провайдер отбрасывается, а не добавляется. Перезапускайте шаг проверки в любое время;
> сбои сообщаются, никогда не скрываются.

## 🧭 Как это работает

```
inbox (one address per account)                                  a fresh address per account
   │
   ├─▶ sign-up: EasyMax page → e-mail address → code / link from the inbox
   ├─▶ session: the account's cookies or access token in hand
   ├─▶ key mint: the account's key endpoint → plaintext key returned once (written to disk immediately)
   └─▶ live proof: POST https://easymax.ai/v1/chat/completions → real content = the key is live
```

| Шаг | Вызов | Примечания |
| --- | --- | --- |
| почтовый ящик | брокер `POST /create` → emailnator → сгенерированный адрес | панель только сохраняет адрес; инструмент никогда не блокируется на почте |
| регистрация | `POST /api/user/register?turnstile= {username,password,email,aff_code}` | именно инвайт-код пополняет аккаунт |
| вход | `POST /api/user/login?turnstile= {username,password}` | `access_token` возвращается в теле |
| аккаунт | `GET /api/user/self` | даёт `id` (→ `New-Api-User`) и `quota`, что доказывает, что инвайт сработал |
| ключ | `POST /api/token/ {name,group,…}` → `POST /api/token/<id>/key` | открытый ключ возвращается один раз |
| проверка | `POST /v1/chat/completions` | требуется живой 200 перед `keys.txt` |

## ⚙️ Опции CLI

```bash
node src/cli.js --count N [--conc N] [--model <id>] [--group <name>] [--pool <file>]
node src/cli.js --dry             # print the resolved plan, touch nothing
node src/cli.js --verify-only     # re-check every key in keys.txt
node src/cli.js --screen          # test the proxy list against EasyMax
```

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `--count` | 5 | аккаунтов (= ключей) для создания |
| `--auto` | вкл. | использовать встроенный решатель капчи (`--no-auto` отключает; в EasyMax нет живой капчи) |
| `--dry` | — | вывести разрешённый план и завершиться (без аккаунтов, без файлов, без сети) |
| `--conc` | 1 | аккаунтов в обработке одновременно (ограничено 16) |
| `--gap` | 1200 | пауза в мс между раундами внутри воркера |
| `--model` | `deepseek-v4.1-flash` | модель, которую использует живой контроль |
| `--group` | `deepseek` | группа токена, в которой создаётся ключ (`default` обслуживает семейство gpt) |
| `--aff` | инвайт-код флота | инвайт-код, отправляемый при регистрации — это источник квоты |
| `--pool <file>` | `proxies.txt` | список выходов (переменная окружения `EASYMAX_PROXIES`) — необязательно: без пула CLI подключается напрямую |
| `--broker <urls>` | `http://127.0.0.1:9700,http://127.0.0.1:9701` | базовый URL(ы) брокера почтовых ящиков |
| `--inbox <chain>` | `broker,emailnator,local` | порядок почтовых каналов |
| `--exits` | 6 | выходов, испробованных на аккаунт, прежде чем он будет оставлен |
| `--verify-only` | — | перезапустить каждый ключ в `keys.txt` через контроль чата |
| `--screen` | — | просеять пул, записать выживших в `proxies.live.txt` |

## 🛰️ За прокси

Каждый запрос к EasyMax идёт через список выходов, когда он предоставлен — **один закреплённый выход на аккаунт**: вызовы регистрации, входа, токена и контроля аккаунта все идут по одной линии, а мёртвый выход передаёт аккаунт следующему в пуле (`--exits`). Туннель встроен: **`http`/`https` CONNECT (с аутентификацией прокси `user:pass@`), `socks5` (включая user/pass) и `socks4a`**.

**Необязательно — рекомендуется при масштабе (лимиты на IP, блокировки).** Инструмент работает и без прокси.

- **С пулом:** передайте `--pool <file>` (или задайте `EASYMAX_PROXIES`) — один закреплённый выход на аккаунт, как выше.
- **Без пула:** CLI выводит `running WITHOUT a proxy (direct)` и подключается напрямую; регистрация, создание ключей и контроль чата не меняются — только пакеты уходят с вашей собственной линии.
- Вызовы брокера почтовых ящиков идут на `localhost` в любом режиме, где ваш собственный брокер выполняет свой исходящий трафик.

## 🔌 Подключение к 9Router

[9Router](https://9router.com) — это самостоятельно размещаемый роутер, совместимый с OpenAI. Одна команда превращает `keys.txt` в узел-провайдер с рабочими комбинациями:

```bash
node src/connect-9router.js
# or: npm run 9router
```

По умолчанию: `--base http://localhost:20128`, `--password 123456`, `--name "EasyMax"`, `--prefix easymax`, `--base-url https://easymax.ai/v1`. Затем модели обслуживаются как `easymax/<model id>` и балансируются между всеми ключами.
