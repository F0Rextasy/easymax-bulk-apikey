## ✨ Зачем это нужно

EasyMax — это панель New API с **регистрацией по обычному имени пользователя + паролю + e-mail** (без подтверждения e-mail), приветственная квота которой зависит от **кода приглашения**: регистрация без кода приводит к `quota: 0`, и её ключ отвечает `403 用户额度不足`, тогда как регистрация с `aff_code` **живого** аккаунта даёт **250000 квоты (≈ $0.50) на аккаунт** — повторно измерено 2026-10-24. Этот код никогда не зашивается в этот репозиторий: инструмент регистрирует один seed-аккаунт и считывает код обратно из панели (`GET /api/user/aff`) перед тем, как начать выпуск, потому что опубликованный код умирает вместе со своим владельцем (код флота, который раньше был здесь, уже оплачивает `quota: 0`). Cloudflare Turnstile **включён** — `src/solver.js` выпускает настоящий токен в offscreen Chrome через тот же выход, поэтому требуются `npm install` (puppeteer-core) и Chrome на машине. Единица масштабирования — *один аккаунт на ключ*; инструмент превращает это в `keys.txt`, где **каждая строка прошла живой вызов чата**, один закреплённый прокси-выход на аккаунт, почтовый ящик из вашего собственного почтового рельса.

## 🎁 Бесплатный тариф — сколько вы получаете

**Каждый аккаунт финансируется кодом приглашения, с которым он регистрируется — а инструмент берёт этот код из самой панели** — вот и весь бесплатный тариф.

| Что | Значение |
| --- | --- |
| Приветственная квота | **250000** (≈ $0.50) на аккаунт, расходуется за токен в группе ключа |
| Откуда она берётся | `POST /api/user/register?turnstile=` с `aff_code=<code>`, где `<code>` — **собственный код живого аккаунта** (`GET /api/user/aff`) |
| Без кода приглашения | `quota: 0` → ключ отвечает `403 用户额度不足` на каждой платной модели |
| Требуется карта | **Нет** |
| Капча | **Cloudflare Turnstile, включена** — настоящий токен, выпущенный в offscreen Chrome через тот же выход (`src/solver.js`; `npm install` + Chrome на машине) |
| Подтверждение e-mail | **не требуется** — панель сохраняет адрес и никогда не отправляет код |
| Единица масштабирования | **один аккаунт = один ключ** → `--count N` на самом деле означает «N профинансированных аккаунтов» |

`--code <code>` закрепляет код приглашения (код вашего собственного аккаунта, который также начисляет вам комиссию панели — 10 % здесь) и пропускает seed-аккаунт; если его не указать, инструмент сначала регистрирует один seed-аккаунт и собирает его код, так что каждый аккаунт запуска финансируется **живым** кодом.

> 💡 Бесплатный тариф устанавливается EasyMax и может измениться. Проверяйте актуальные цифры на [easymax.ai](https://easymax.ai) — и пусть собственный гейт инструмента решает:

```bash
node src/cli.js --verify-only     # every key in keys.txt is re-tested with a real chat call
```

## 🧪 Как использовать API

Базовый URL — **`https://easymax.ai/v1`** — совместим с OpenAI, поэтому работает всё, что говорит на OpenAI (SDK, Cursor, OpenCode, Kilo Code, …).

```bash
curl https://easymax.ai/v1/chat/completions \
  -H "Authorization: Bearer <your key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4.1-flash","messages":[{"role":"user","content":"hi"}],"max_tokens":16}'
```

Id `deepseek-v4-pro` — это reasoning-модель: она отвечает сначала `reasoning_content`, а `content` только после бюджета размышления, поэтому задавайте `max_tokens` значительно выше 100, иначе увидите пустой `content`.

## 🚀 Одна команда

```bash
node src/cli.js --count 10
```

Это весь инструмент: один аккаунт EasyMax на ключ (профинансированный кодом приглашения, который возвращает панель), его API-ключ выпускается и сохраняется **только** после живого `chat-200`. Шаг с капчей тоже автоматический — панель использует Cloudflare Turnstile, а `src/solver.js` (включён по умолчанию за `--auto`) выпускает настоящий токен в offscreen Chrome **через тот же выход**, потому что токен привязан к IP, решающему капчу; для этого и нужен однократный `npm install`. Файл `proxies.txt` рядом с репозиторием подхватывается автоматически (один закреплённый выход на аккаунт); без него запуск идёт напрямую.

`--dry` выводит разрешённый план — количество, размер пула, доступность решателя, модели — и завершается, не трогая ни одного файла и не делая ни одного запроса:

```bash
node src/cli.js --dry
```

Предпочитаете меню вместо флагов? `npm start` (или `node src/launcher.js`) → **1) Mint keys** → *How many keys? [10]*.

> ⚠️ **Условия и риск для аккаунта.** Этот инструмент автоматизирует создание аккаунтов и выдачу API-ключей на сторонней панели. Это может нарушать Условия обслуживания панели и привести к блокировке аккаунтов, ключей или IP. **Автоматизация — ваша собственная ответственность**: прочитайте условия провайдера, используйте свой собственный почтовый ящик и прокси и убедитесь, что вам разрешено это делать там, где вы живёте, прежде чем запускать.

# clone or fork this repository, then:

Ключ добавляется в `keys.txt` **только** после того, как живое завершение чата подтвердит его; аккаунт, который так и не дошёл до этой точки, записывается в `accounts.json` и повторяется при следующем запуске.

### 🖱️ Лаунчер

`npm start` (или `node src/launcher.js`) — это меню-форма того же CLI: **1) Mint keys** → *How many keys? [10]* (Enter принимает 10) запускает `node src/cli.js --auto --count N`. Он никогда не спрашивает о капче, токене или прокси — `proxies.txt` используется автоматически, если присутствует. Он завершается сводной таблицей (живые/всего, задержка, классы ошибок) плюс путь к `keys.txt`; ключи, не прошедшие гейт, попадают в `keys-dead.txt`.

## ✅ Проверено в работе — каждый ключ протестирован

| Проверка | Результат |
| --- | --- |
| регистрация `POST /api/user/register?turnstile=` | **200** `{"success":true}` — с живым `aff_code` аккаунт получает `quota: 250000` |
| Turnstile при регистрации | требуется настоящий токен (`Turnstile 校验失败` без него), и он выпускается именно с того выхода, который его тратит |
| вход `POST /api/user/login?turnstile=` | **200** — полезная нагрузка New-API **v2** (`access_token` JWT + сессия) |
| авторизация | `Authorization: Bearer <access_token>` + `New-Api-User: <uid>` на `/api/token/*` |
| ключ | `POST /api/token/ {group}` → **200**, затем `POST /api/token/<id>/key` → полный ключ |
| гейт чата — выполняется для **каждого** ключа перед записью | **200** с реальным содержимым |
| ключ, не прошедший проверку чата | никогда не записывается в `keys.txt` (аккаунт остаётся пригодным для повторного использования в `accounts.json`) |

Создано этим инструментом во время сборки: **8 аккаунтов / каждый ключ, все `quota 250000`, все chat-200** на `deepseek-v4.1-flash`, через два типа туннелей (CONNECT + SOCKS5) и 4 выхода. Повторно измерено 2026-10-24 через собственный CLI этого репозитория (`--count 1`, один выход WARP): собственный код seed-аккаунта профинансировал созданный аккаунт с `quota 250000`, и его ключ ответил chat-200 на двух разных запросах.

> **Контроль качества.** Каждый ключ здесь прошёл живой `chat-200` прежде, чем был записан в `keys.txt`
> (мёртвые ключи никогда не поставляются). Комбинации роутера следуют тому же правилу на уровне модели: запись
> добавляется **только если модель отвечает `chat-200` и умеет вызывать инструменты** — модель без поддержки инструментов,
> мёртвый ключ или мёртвый провайдер отбрасывается, а не добавляется. Повторяйте шаг проверки в любое время;
> сбои сообщаются, никогда не скрываются.

## 🧭 Как это работает

```
inbox (one address per account)                                  a fresh address per account
   │
   ├─▶ sign-up: EasyMax page → e-mail address → code / link from the inbox
   ├─▶ session: the account's cookies or access token in hand
   ├─▶ key mint: the account's key endpoint → plaintext key returned once (written to disk immediately)
   └─▶ live proof: POST https://easymax.ai/v1/chat/completions → real content = the key is live
```

| Шаг | Вызов | Примечания |
| --- | --- | --- |
| капча | `src/solver.js` — offscreen Chrome, привязанный к выходу аккаунта | Turnstile включён и привязывает свой токен к IP, который его тратит |
| код приглашения | один seed-аккаунт → `GET /api/user/aff` | собственный ответ панели — это код, с которым регистрируется каждый аккаунт запуска (`--code` закрепляет вместо этого один) |
| почтовый ящик | брокер `POST /create` → emailnator → сгенерированный адрес | панель только сохраняет адрес; рельс никогда не блокируется на почте |
| регистрация | `POST /api/user/register?turnstile= {username,password,email,aff_code}` | код приглашения — это то, что финансирует аккаунт |
| вход | `POST /api/user/login?turnstile= {username,password}` | `access_token` возвращается в теле |
| аккаунт | `GET /api/user/self` | даёт `id` (→ `New-Api-User`) и `quota`, что доказывает, что приглашение сработало |
| ключ | `POST /api/token/ {name,group,…}` → `POST /api/token/<id>/key` | открытый ключ возвращается один раз |
| проверка | `POST /v1/chat/completions` | требуется живой 200 перед `keys.txt` |

## 🛰️ За прокси

Каждый запрос к EasyMax идёт через список выходов, когда он предоставлен — **один закреплённый выход на аккаунт**: вызовы регистрации, входа, токена и гейта аккаунта все едут по одной линии, а мёртвый выход передаёт аккаунт следующему в пуле (`--exits`). Туннель встроен: **`http`/`https` CONNECT (с аутентификацией прокси `user:pass@`), `socks5` (включая user/pass) и `socks4a`**.

**Необязательно — рекомендуется при масштабе (лимиты на IP, блокировки).** Инструмент работает и без прокси.

- **С пулом:** передайте `--pool <file>` (или задайте `EASYMAX_PROXIES`) — один закреплённый выход на аккаунт, как выше.
- **Без пула:** CLI печатает `running WITHOUT a proxy (direct)` и подключается напрямую; регистрация, выпуск ключей и гейт чата не меняются — только пакеты уходят с вашей собственной линии.
- Вызовы брокера почтовых ящиков идут на `localhost` в любом режиме, где ваш собственный брокер делает свой собственный выход.

## 🔑 Что даёт один ключ

| | |
| --- | --- |
| 🏢 Провайдер | **EasyMax** — [easymax.ai](https://easymax.ai) |
| 🎁 Что даёт провайдер | один аккаунт на ключ — регистрация по коду приглашения финансирует его, каждый ключ проверен чатом |
| 🔑 Что даёт один ключ | один API-ключ, привязанный к своему собственному аккаунту: 5 id моделей на эндпоинте ниже, в пределах лимитов вашего тарифа. Квота живёт на **аккаунте**, и именно поэтому этот инструмент создаёт один аккаунт на ключ |
| 🌐 Форма API | совместим с OpenAI: `POST https://easymax.ai/v1/chat/completions` |
| 🔒 Ваши данные | связываются только easymax.ai и настроенный вами бэкенд почтовых ящиков; ключи остаются на вашей машине |

## 🐞 Проблемы

Если панель изменит форму регистрации, отменит бонус за приглашение или переименует свои группы, инструмент остановится на этом шаге и сообщит об этом. **[Откройте issue](../../issues)** с командой, которую вы запустили, и точным выводом; PR приветствуются.
